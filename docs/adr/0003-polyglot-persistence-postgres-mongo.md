# 0003. Разные хранилища: PostgreSQL (write) + MongoDB (read)

- **Статус:** Accepted
- **Дата:** 2025-09-23

## Контекст

Сторона записи требует транзакционности и целостности данных, сторона чтения —
быстрого доступа по идентификатору и возможности гибко менять структуру read-модели.
Одно хранилище на обе роли — компромисс по обеим осям.

## Решение

- **PostgreSQL** — для command-сервиса (ACID-транзакции, реляционная модель);
- **MongoDB** — для query-сервиса (документная read-модель, быстрый доступ по `id`).

## Последствия

**Плюсы:**
- каждая сторона использует инструмент, подходящий под её нагрузку;
- read-модель можно менять независимо от модели записи.

**Минусы:**
- два хранилища в эксплуатации (бэкапы, мониторинг, образы);
- сложнее локальная разработка и интеграционные тесты (нужны оба).
