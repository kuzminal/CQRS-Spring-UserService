# 0004. Дублирование контракта события между сервисами

- **Статус:** Accepted
- **Дата:** 2025-09-23

## Контекст

Класс `UserCreatedEvent` нужен обоим сервисам: command-сервис его производит (сериализует
в JSON), query-сервис потребляет (десериализует из JSON). Рассматривались варианты:
общая библиотека-контракт или дублирование класса в каждом сервисе.

## Решение

Дублировать класс `UserCreatedEvent` в каждом сервисе, не вынося в общий модуль.
Контракт события задаётся JSON-структурой (id, username, email) и версионируется
по имени/версии события, а не по общему артефакту.

## Последствия

**Плюсы:**
- полная независимость сервисов — нет связанности через общий артефакт;
- нет «библиотеки, которая тормозит деплой всех» (shared-library coupling).

**Минусы:**
- риск рассинхронизации контракта при изменении — нужна дисциплина и версионирование;
- дублирование кода сериализации/десериализации.
