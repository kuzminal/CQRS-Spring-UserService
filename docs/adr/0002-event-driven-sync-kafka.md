# 0002. Синхронизация read-модели через Kafka

- **Статус:** Accepted
- **Дата:** 2025-09-23

## Контекст

Read-модель (MongoDB) должна обновляться после записи в command-сервисе (PostgreSQL).
Рассматривались варианты: синхронный REST-вызов между сервисами, общая база данных и
асинхронные события через брокер.

## Решение

Command-сервис публикует доменное событие `UserCreatedEvent` в топик Kafka `user-events`,
query-сервис подписывается на топик и обновляет read-модель. Согласованность — eventual.

## Последствия

**Плюсы:**
- полная развязка сервисов: command-сервис не знает о потребителях;
- возможность replay событий для восстановления read-модели;
- независимое масштабирование потребителей.

**Минусы:**
- eventual consistency — между записью и появлением данных в read-модели есть задержка;
- контракт события нужно синхронизировать между сервисами (см. ADR-0004).
